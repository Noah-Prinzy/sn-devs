### shadcn/ui — https://ui.shadcn.com
- **What it is:** The de facto standard "not a component library" — a collection of composable, accessible React components whose source code you copy into your project and own ("The Foundation for your Design System"). ~128k GitHub stars, built by shadcn at Vercel. Its registry format has become the *distribution protocol* the whole ecosystem now builds on.
- **Design language:** Neutral, restrained, monochrome-default aesthetic with light/dark theming via CSS variables. "Thoughtful defaults" — the canonical tasteful SaaS/dashboard look (finance dashboards, settings pages, AI chat). No opinions forced; it's a starting point you restyle.
- **Component catalog highlights:** Full primitive suite (Button, Badge, Alert Dialog, Dialog, Button Group, etc.), plus Charts, Blocks (complete dashboard/login/settings compositions), Typeset, Directory, and new AI-era pieces (Trace, Code Block, AI Elements). The demo homepage itself is a masterclass: banking dashboards, dividend trackers, notification preference panels, streaming AI chat.
- **Install / integration:** `npx shadcn add <component>` CLI into your repo; you own and edit the code. Registry system now supports third-party namespaces (`@componentry`, `@skiper-ui`, `@amicro`) via the same CLI. MCP support for AI agents.
- **Stack & dependencies:** React, Tailwind CSS, Radix UI primitives (accessibility), class-variance-authority (variants), tailwind-merge + clsx, lucide-react icons. Built by shadcn at Vercel; open source.
- **Skills to steal:** CSS-variable theming driven by `data-theme` attributes; `cva()` variant architecture for component APIs; Radix `asChild` slot composition; the registry-distribution model (anyone can ship a namespaced registry the CLI understands); docs as living product (every example is a real composition, not a widget in isolation).

### Watermelon UI — https://ui.watermelon.sh
- **What it is:** An open-source React UI *platform* — a curated catalog combining animated components, copy-paste blocks, dashboards, and templates, "for developers who want strong visual references and real implementation paths at the same time." Free, maintained in public by WatermelonCorp (`watermelon-platform` repo).
- **Design language:** Production-style reference catalog rather than one house aesthetic; positioning is "from inspiration to shipping" — full realistic compositions instead of isolated widgets.
- **Component catalog highlights:** Animated components (interaction-heavy), Blocks (landing-page/product sections), Dashboards (full layouts), Templates (starting points). Also Auth docs and an MCP server.
- **Install / integration:** Copy-paste with documented paths; uniquely agent-first — publishes `llms.txt`, `sitemap.xml`, an OpenAPI spec, and an MCP server (`mcp.watermelon.sh`) as first-class "developer resources."
- **Stack & dependencies:** React/Next.js ecosystem, Tailwind-oriented; maintainability emphasized; open platform source on GitHub.
- **Skills to steal:** Machine-readable catalogs for AI agents (llms.txt + OpenAPI + MCP as the modern docs triad); the "inspiration → implementation" pipeline where every visual reference links to real code; organizing a library by product area (components/blocks/dashboards/templates) rather than alphabet.

### Componentry — https://componentry.dev
- **What it is:** "The component library for polished interfaces" — 54 animated React components with editable source code, by Harsh Jadhav. Backed by the Vercel OSS Program (~465 stars), sponsor-supported via Polar.
- **Design language:** Playful high-craft "design engineer showcase" — experimental texture and media effects: dithering, ASCII, particles, liquid chrome, split-flap displays, WebGL. Very strong visual identity; the docs sidebar with hover previews is itself praised for spacing and cleanliness.
- **Component catalog highlights:** Animated/Prism/Dither/Grain gradients, Aurora Flow, Silk Aurora, ASCII Effect, Circuit Board, Matrix Rain, Cursor-driven Particle Typography, Image Ripple, Image Trail, Infinite Image Field, Liquid Chrome, WebGL Liquid, Kinetic Text Reveal, Flipping Word Swap, Text Morph/Repel, Letter Cascade, Scroll Choreography, Scroll Split Card, Sticky Scroll Cards, Velocity Scroll, Magnetic Dock, Fisheye Infinite Grid, Split Flap Display, Mac Keyboard, Flight Status Card, Github Calendar, Music Player, Spiral 3D Slider, Wheel Carousel, Eye Tracking, Lens Clock, Signature. Plus Blocks and Collections.
- **Install / integration:** shadcn CLI with its own namespace — `npx shadcn add @componentry/cursor-driven-particle-typography`; also installable via AI editors through MCP (`/docs/mcp`).
- **Stack & dependencies:** React, Tailwind CSS, Motion; some components use canvas/WebGL. Free + sponsorship; author takes custom component commissions.
- **Skills to steal:** Cursor-driven particle systems and text-repel physics; dithering/ASCII as retro-texture devices; scroll choreography patterns (split cards, tilted grids, sticky sequences); magnetic/fisheye spatial interactions; proof that a one-person library can win distribution purely through the shadcn registry namespace + tasteful demo craft.

### Skiper UI — https://skiper-ui.com
- **What it is:** 106+ components *for* shadcn/ui — each component is a single file with "no extra packages," installable through the standard shadcn CLI. By Gxuri (@Gur__vi). Free tier + one-time-purchase Premium ($129; $549 "Exclusive" adds Figma files and full website templates).
- **Design language:** Motion-rich, delightful micro-interactions explicitly inspired by Rauno Freiberg's "Devouring Details" (devouringdetails.com) — fluid springs, cursor-aware behavior, physicality. Demos are video-first, showing interactions rather than static shots.
- **Component catalog highlights:** Image reveal, Hover members (team cards), drag-and-scroll lists, "Devouring Details"-style sign-in, Dynamic Island, Vercel-style tooltip, Aave token-swap widget, image cursor trails. Free vs Premium split within the same catalog.
- **Install / integration:** `npx shadcn add @skiper-ui/skiper40` — a namespaced shadcn registry; one file per component, zero additional runtime dependencies.
- **Stack & dependencies:** Tailwind CSS, Next.js, Motion (motion.dev); positioned alongside v0 workflow.
- **Skills to steal:** Single-file component discipline (drop-in, no dep tree); Devouring Details principles — spring-based transitions, attention to press/hover states, cursor-following elements; OS-style patterns (Dynamic Island, split-flap, keyboard) translated to the web; the business model of free-core + one-time premium without subscriptions.

### Amicro — https://amicro.vercel.app  ⚠ *direct fetch failed (HTTP 429); reconstructed from websearch of official/first-party sources*
- **What it is:** "Small motion. Big difference." — a free, open-source (MIT) library of 170+ copy-paste React micro-interaction components by Syed Subhan (@SubhanHQ). Vercel OSS '26, ~2.6k stars. Categories: animated buttons, 3D card spreads & carousels, canvas loaders, shape morphs, text animations, mono telemetry charts, dither charts.
- **Design language:** Premium-feel micro-transitions: fluid, responsive, tuned durations and easing; dark- and light-mode-ready. Tagline philosophy — tiny motion details doing the heavy lifting.
- **Component catalog highlights:** Animated buttons (glow/lift), 3D card spreads and carousels, canvas-based loaders, shape morphs, text animations, telemetry-style charts and dither charts on a tiny canvas engine.
- **Install / integration:** Dual path — shadcn registry (`npx shadcn@latest add @amicro/pulse-dots`) and its own CLI (`npx @subhanhq/amicro@latest init` / `add`). Zero runtime overhead: TSX source is copied directly into your codebase.
- **Stack & dependencies:** React 18/19 + TypeScript, Tailwind CSS v4, Motion (`motion/react`). Works in Next.js (App & Pages router), Vite, Remix — any React + Tailwind setup.
- **Skills to steal:** A complete micro-animation spec worth adopting as defaults: GPU-friendly transform/opacity only, 200–350ms micro-transition durations, ease curve `[0.16, 1, 0.3, 1]`, `prefers-reduced-motion` respected everywhere; motion primitives + custom hooks + spring presets distributed *through* the shadcn registry; copy-into-agent workflow (paste a component into your prompt so the AI can recreate the interaction).

### Bencho — https://bencho.dev
- **What it is:** "Interactive UI Components" — a library of interactive React components and micro-interactions you explore and "take straight into your projects." Sections: Blocks, Sounds, Finds, Bench, Pricing — suggesting free + paid mix (pricing details not exposed on homepage).
- **Design language:** Interaction-first taxonomy: the entire catalog is indexed by gesture — Press, Hover, Drag, Type, Swipe, Select, Loading. The library reads as a study of tactile, stateful micro-interactions rather than themed components.
- **Component catalog highlights:** ~170 blocks: AI Assistant, AI autocomplete, AI chat input, Genie effect, flap board, jelly tabs, slingshot, crumpled receipt (drag), page peel, pull-to-refresh, slide-to-confirm, signature pad, one-time code input, password strength, dynamic island, orders globe, price chart, rolling counter, time scrubber, world clock, metaballs, dot swarm, magnetic letters/select, radial menu, option wheel, split view, resizable panels, tree view, upload dropzone, confetti, piano, plus a full loaders family (wave/bounce/trace/morph/pixel/blocks) and UI sounds as a first-class section.
- **Install / integration:** Copy/paste "take straight into your projects"; pricing page implies a paid tier for premium blocks. No registry/CLI advertised on the homepage.
- **Stack & dependencies:** React; animation-heavy (Motion-style springs/drag physics); sound assets included.
- **Skills to steal:** The gesture-based taxonomy itself — document every component by the interaction it demonstrates (Press/Hover/Drag/Type/Swipe/Select/Loading); physical-world interactions (page peel, crumpled receipt, folding bill, slingshot, pull-to-refresh) done in DOM; sound design as a named library concern; treating loaders and form feedback as a designed category, not an afterthought.

### HeroUI (formerly NextUI) — https://heroui.com
- **What it is:** A full ecosystem: free open-source components for **React and React Native** (set your theme once, works on web and mobile), HeroUI Pro (premium components/templates/themes), HeroUI Agents (embeddable generative-UI agent, beta), and HeroSpace (agent-powered Mac workspace, alpha). YC-backed; 31.1k stars on core repo (38.1k combined), 26.6M+ monthly npm downloads. Used by Apple, ByteDance, NAB, Toptal and others.
- **Design language:** Modern, sleek, beautiful-out-of-the-box — the anti-shadcn pitch ("less to maintain and things look good right away"). Web Theme Builder tunes hue, chroma, lightness, radius, font, form radius live. Template aesthetics span Default, GlassMouve, and Brutalism.
- **Component catalog highlights:** Core: complete accessible component suite for React + React Native. Pro: Command menu, Kanban, Stats/KPI, Filters, Agenda, DataGrid; full templates for Dashboard, Mail, Chat, CRM, Finance — same design language on web, iOS, Android.
- **Install / integration:** Traditional npm package import (library-style, not copy-paste); provider-based configuration. Also CLI, MCP servers (React, Native, Pro, Agents), agent skills, llms.txt and AGENTS.md for coding agents, plus a published "Design Taste" guide.
- **Stack & dependencies:** React + React Native/Expo, Tailwind CSS, **Tailwind Variants** (their own slot-styling library, a standalone OSS project), Framer Motion for animations; commonly paired with TanStack + Convex by users.
- **Skills to steal:** Tailwind Variants slot architecture — multi-part components (e.g., Card has header/body/footer slots) styled from one `tv()` definition; theme-token design (single theme drives web + native); the Theme Builder parameterization (hue/chroma/lightness/radius as design tokens); treating AI agents as a distribution channel (MCP + skills + AGENTS.md + design-taste docs); generative-UI agent pattern where the agent renders interfaces gated by user permissions.

## Category Synthesis

**Copy-paste / registry libraries (shadcn/ui, Componentry, Skiper UI, Amicro, Aceternity, Bencho, Watermelon UI) vs npm libraries (HeroUI):**

- **Ownership vs dependency.** Copy-paste libraries put the actual TSX source in your repo — you own it, can gut it, restyle it, or let it rot. npm libraries (HeroUI, the classic MUI/Chakra model) ship versioned, tested packages behind a stable API — updates are a `npm update` away, but customization happens inside the library's theming escape hatches, not the component internals.
- **Maintenance math.** Copy-paste means every upstream fix must be re-imported by hand (the CLI can diff, but it's on you); npm means upgrades are cheap but fighting the library's opinions is expensive. HeroUI's own community pitches this trade-off explicitly: "ditched shadcn lately in favour of HeroUI — less to maintain and things look good right away."
- **Consistency guarantees.** npm libraries with a token/slot system (HeroUI's Tailwind Variants + theme provider) enforce a single design language across hundreds of surfaces automatically. Copy-paste stacks drift unless you discipline them with CSS-variable themes (shadcn's approach) — which is exactly why shadcn made tokens, not components, the foundation.
- **When to choose which.** Choose **npm (HeroUI-style)** for product teams shipping many internal/admin surfaces fast, wanting accessibility + polish by default, and mobile parity (HeroUI Native). Choose **copy-paste (shadcn-style)** when design differentiation is the product — marketing sites, portfolios, startups wanting a unique feel — or when you need AI agents to modify component internals freely (agents can't edit node_modules source, but they can edit your copied TSX). Choose **registry libraries (Componentry/Skiper/Amicro/Aceternity)** when you want a specific effect or block today: they give copy-paste ownership with npm-like one-command ergonomics.
- **How they complement each other in a real project.** A common 2026 architecture: **shadcn/ui as the accessible structural base** (forms, dialogs, dropdowns — the boring 80%), **HeroUI-style tokens or shadcn CSS variables** as the theming layer, **one registry library for motion personality** (Amicro micro-interactions, Skiper/Componentry showpieces), and **Aceternity blocks for marketing surfaces** (hero, pricing, testimonials) that deliberately look different from the app. The unifying insight: the shadcn CLI registry format became the *interchange standard* — six of the eight libraries here install through it — so mixing them is genuinely low-friction. The real skill is layering: primitives from one place, motion tuning from another (Amicro's 200–350ms / `[0.16, 1, 0.3, 1]` / reduced-motion defaults are a good house standard), and page-scale composition from a third.
