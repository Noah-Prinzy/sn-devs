### Design Prompts (designprompts.dev) — https://designprompts.dev

- **What it is:** A free, no-signup "design prompt compiler" for AI coding agents. You pick a **page template** (12 options: SaaS launch, Mobile app, Waitlist, Developer tool, Studio, Portfolio, Shop, Local business, Event, Course, Nonprofit, Newsletter) and a **look** (48 named aesthetic presets), preview the combined result on desktop/mobile, then export the generated prompt to feed your coding agent. Companion products: **LandingKit** (1,200+ React blocks in 21 styles, "optimized for agents") and a **Premium Gallery** of complete design systems with full React code, assets, and agent skills.
- **Design language:** Each "look" is a compact, opinionated design system with an evocative name and a one-sentence spec — e.g. *Bare Metal* (black/white, thin grids, white pill button, developer platforms), *Paper Trail* (serif headlines, color reserved for product imagery, B2B), *Terminal* (serif headlines + monospaced text, CLIs/infrastructure), *Night Launch* (product screenshots with red glow, dev/AI products), *Sorbet* (pastel backgrounds + 3D product displays, beauty/gift shops), *Main Street* (warm, light, photographic for bakeries/cafés), *Study Hall* (butter-yellow paper, friendly type, diagrams, courses), *Field Report* (big figures, charts, ruled rows, impact reports).
- **Key features / tools:** Matrix architecture (template × look × preview); 12 section-structure recipes per page type; 48 look presets each tied to an industry niche; Builder mode for editing; desktop + mobile preview before committing; Pro tiers shipping React block libraries and design-system files.
- **UI patterns to learn:** (1) Page-type → section-mapping: a "SaaS launch" = product + customer proof + pricing + signup; "Developer tool" = installation-first + alternatives comparison + docs/changelog; "Course" = what you learn + who teaches + price. (2) Look descriptions encode a full recipe in one sentence: typography family/mood + color role + imagery treatment + target vertical. (3) Industry-constraint thinking: every look names who it's for, teaching the agent *why* the palette matches the vertical.
- **Skills to steal:** The 12×48 matrix format — express design systems as `{page-type} × {named look}` instead of one giant prompt. Steal the one-sentence look formula: `[typography] + [color treatment] + [imagery style] + [for X industry]`. Steal the "preview before commit" UX for any agent design tool. Steal its page-type section recipes as default landing-page skeletons (e.g., install-first heroes for dev tools, proof-before-pricing for SaaS).

### Awesome DESIGN.md (VoltAgent) — https://github.com/VoltAgent/awesome-design-md

- **What it is:** A curated, MIT-licensed collection of **84 DESIGN.md files** — plain-text design system documents extracted from real websites (Claude, Vercel, Stripe, Linear, Apple, Nike, Tesla, Spotify, IBM, Shopify, 40+ more, grouped by industry: AI/LLM, dev tools, backend/DevOps, SaaS, design tools, fintech, e-commerce, media, automotive, plus a "Retro Web" nostalgia series for 1990s/2000s UIs). ~126k stars. The DESIGN.md concept comes from **Google Stitch**: one markdown file at project root that any AI agent reads to generate consistent UI — the "design-side" twin of AGENTS.md.
- **Design language:** Whatever brand you pick — each file codifies it: e.g., Linear = ultra-minimal, precise, purple accent; Vercel = black/white precision, Geist font; Stripe = purple gradients, weight-300 elegance; Supabase = dark emerald, code-first; Tesla = "radical subtraction", cinematic full-viewport photography.
- **Key features / tools:** Every DESIGN.md follows the 9-section Stitch spec: (1) Visual Theme & Atmosphere, (2) Color Palette & Roles (semantic name + hex + functional role), (3) Typography Rules (families + full hierarchy table), (4) Component Stylings (buttons/cards/inputs/nav **with states**), (5) Layout Principles (spacing scale, grid, whitespace philosophy), (6) Depth & Elevation (shadow system, surface hierarchy), (7) Do's and Don'ts (guardrails, anti-patterns), (8) Responsive Behavior (breakpoints, touch targets, collapsing strategy), (9) **Agent Prompt Guide** (quick color reference + ready-to-use prompts). Each entry ships with `preview.html` and `preview-dark.html` visual catalogs (swatches, type scale, buttons, cards).
- **UI patterns to learn:** The 9-section DESIGN.md structure is the canonical skeleton for any agent-readable design doc. Key insight: keep **token, rule, and rationale in the same file** — a Figma export says *what*, a brand PDF says *why* loosely, DESIGN.md says both at agent precision. The Do's/Don'ts section as executable guardrails; semantic color roles (not just hex values); component definitions including hover/focus/disabled states.
- **Skills to steal:** Adopt the exact 9-section template for designIQ's design-system files. Steal the paired-artifact pattern (machine-readable doc + human `preview.html` to visually verify). Steal its one-line brand summaries as a taxonomy of named aesthetics. Steal the workflow: "copy file into project root → tell agent to build" — zero parsing, zero tooling, markdown as the lingua franca.

### Awesome Claude Design (VoltAgent) — https://github.com/VoltAgent/awesome-claude-design

- **What it is:** Companion repo (~4.4k stars) with **68 DESIGN.md system inspirations** formatted to be dropped into **Claude Design** (Anthropic's design workspace at claude.ai/design), which scaffolds a full design system — colors, type, components, preview cards, working UI kit — in one shot. Two ingestion paths: (A) create a new design system and upload the DESIGN.md as an asset, or (B) attach it in a prototype chat and say "Create a design system from this DESIGN.md".
- **Design language:** Same getdesign.md library (Claude, Cursor, Raycast, Stripe, Notion, Ferrari, Lamborghini, etc.), but this repo documents the **downstream artifacts** Claude produces from one file: `README.md` (brand context, voice, visual foundations), `colors_and_type.css` (CSS variables, type scale, utility classes), Google Fonts substitutes when brand fonts are proprietary, `preview/` cards (colors, type, spacing, components, brand), a working `index.html` UI kit applying the system to a real marketing page, and **`SKILL.md`** — a portable skill file for reuse in future projects.
- **Key features / tools:** One-markdown-file → production-ready design package pipeline. Options A (system-first) vs B (prototype-first) ingestion. Tips section: start in a fresh project (mixing brands muddles tokens); keep requesting screens ("now build a pricing page") to stay on-brand automatically; request variants (light/dark, compact/comfortable, marketing/app); **export the SKILL.md** to re-summon the same aesthetic anywhere without re-uploading.
- **UI patterns to learn:** The DESIGN.md→scaffold pipeline shows how a design doc maps 1:1 to concrete deliverables (CSS variables, type scale, preview cards, UI kit). The variant-branching idea: one base token set cleanly derives light/dark and compact/comfortable variants. The SKILL.md concept: a design system distilled into a portable, re-invocable agent skill.
- **Skills to steal:** The full output manifest (README + colors_and_type.css + previews + UI kit + SKILL.md) as the definition of "done" for design system scaffolding. The Google-Fonts-substitution trick for proprietary typefaces. The fresh-project/token-hygiene rules. ### Astro (astro.build) — https://astro.build

- **What it is:** An open-source (MIT) **JavaScript web framework optimized for content-driven websites** — marketing sites, blogs, docs, e-commerce. Current release Astro 7.4. Core pitch: render on the server, ship lightweight HTML **with zero unnecessary JavaScript**; used by major companies; #1 in real-world Core Web Vitals (71% passing vs WordPress 48%, Gatsby 45%, Next.js 35%, Nuxt 28% per HTTP Archive/Chrome UX Report).
- **Design language:** N/A (framework) — but its site design reflects its philosophy: performance-first, content-forward, developer-minimal. `npm create astro@latest` one-liner, docs-first marketing.
- **Key features / tools:** **Islands architecture** — the page is static HTML with discrete interactive components ("islands") hydrated individually via `client:load`/`client:visible`-style directives; **zero JS by default** (unneeded JS stripped automatically); **framework-agnostic islands** (React, Vue, Preact, Svelte, Solid, Qwik, Angular — zero lock-in, mix frameworks on one page); **Content Collections** (Markdown/MDX with TypeScript type-safety and frontmatter validation); built-in **View Transitions**; **Optimized Images** (no layout shift, modern formats); file-based routing; middleware; **Actions** (type-safe backend functions callable from client JS); deployment adapters (Node, Cloudflare, Vercel, Netlify, AWS, Deno); intelligent prefetching; Dev Toolbar; environment variables API; and **AI-ready tooling** (official MCP server + context files for AI tools). Frontmatter code-fence templating (`.astro` files): if you know HTML you can write components.
- **When to choose Astro over Next.js/React SPA:** Choose Astro when content drives the site — marketing, blogs, docs, landing pages, e-commerce content pages — where SEO, Core Web Vitals, and load speed dominate and only a few widgets need interactivity (a buy button, a search box). Next.js/React SPA wins for app-like products with heavy shared client state, auth-gated dashboards, and dense interactions on every screen. Astro's rule of thumb: if most of your page is text and images with occasional interactive islands, ship an Astro page; if most of your page is state, ship React. Astro deliberately coexists with React — an Astro shell can host React islands where needed, so "Astro vs Next" is really "static-first vs app-first".
- **Content-driven site strengths:** Content Collections give typed, validated frontmatter for Markdown/MDX (CMS or filesystem as source); built-in optimized images and prefetching; View Transitions for app-like navigation between content pages; server-first rendering keeps bundles tiny. Its own CWV data (71% vs 35% for Next.js) is the strongest evidence.
- **Template/theming ecosystem:** Official **Themes gallery** categorized into Trending, E-Commerce, Blogs, Docs, Portfolios, Landing Pages — including **Starlight** (the official docs theme), AstroShip, Upstart, Prima Persona, Darkrise, Dante, Brutal, OpenBlog, Astrofy, Swissfolio, Positivus, and more; starter templates via astro.new; integrations marketplace; partner agencies program. Themes are full working sites meant to be customized — effectively pre-built design systems in code.
- **UI patterns to learn:** Islands = a first-class architecture for "mostly static with interactive accents"; `client:` directives as an explicit hydration contract; typed frontmatter schemas as a content-design contract; docs site (Starlight) as a standard for developer-content layouts.
- **Skills to steal:** The islands mental model for any agent deciding hydration scope. The Themes-gallery taxonomy (e-commerce/blogs/docs/portfolios/landing) as a content-site classification. The "AI-ready" pattern: ship an MCP server + context files so AI tools know your framework — directly relevant to designIQ's goal. The code-fence component format as the most agent-friendly templating syntax (HTML + JS frontmatter, no new DSL).

## Category Synthesis

**How AI design prompts & skills improve AI-assisted frontend work.**

1. **Design context as a file is the core unlock.** The DESIGN.md movement (Google Stitch → awesome-design-md → awesome-claude-design → UI UX Pro Max's MASTER.md) shows a convergence on one idea: an AI agent produces consistent, high-quality UI only when given a *structured design document* — tokens, rules, and rationale together — in plain markdown, the format LLMs read best. The canonical schema: theme/atmosphere → semantic colors with roles → type scale → components **with states** → layout/spacing → depth/shadows → do's & don'ts → responsive behavior → ready-to-use prompts. Any AI frontend workflow should start by generating or adopting such a file, not by prompting adjectives ("make it modern").
2. **Rationale beats raw values.** A Figma export says *what*; a brand PDF says *why* too loosely. The winning format keeps token + rule + rationale in one file, so when the agent hits a case the file never covered, it extrapolates *on-system* (awesome-claude-design's "stays on-brand automatically" when you keep requesting screens). Anti-patterns are as valuable as rules — "no neon for banking", "no AI purple/pink gradients" — because they prune the agent's failure modes cheaply.
3. **Retrieval + reasoning engines beat long prompts.** UI UX Pro Max operationalizes design knowledge: BM25 search across 80 styles / 192 palettes / 74 font pairings / 192 industry reasoning rules → one structured spec → hard pre-delivery checklist. The transferable architecture: (a) parallel multi-domain search, (b) industry-conditioned rules, (c) negative constraints, (d) checklist gates (contrast 4.5:1, focus states, reduced-motion, 375–1440px reflow). A hierarchy of `MASTER.md` + per-page override files makes the system persist across sessions — the "memory" layer for design.
4. **Composability: page-type × look.** designprompts.dev proves that a design brief decomposes into two mostly-independent axes — *what the page must contain* (12 section recipes: SaaS launch, dev tool, course…) and *how it should feel* (48 one-line look specs: typography + color treatment + imagery + vertical). Prompt techniques follow: give the agent a section skeleton plus a named aesthetic, and demand a preview loop before code is finalized.
5. **Portability via skills and previews.** The `SKILL.md` export (Claude Design), the paired `DESIGN.md` + `preview.html` artifacts, and Astro's MCP-server-for-AI pattern all point the same way: design knowledge should ship as small, portable, self-verifying artifacts that any agent — and any human — can inspect.

**When to start from a template vs build from scratch.**

- **Start from a template** when: the project matches a known genre (SaaS landing, portfolio, restaurant, docs); speed and proven layout/responsive behavior matter more than uniqueness (HTML5 UP, FreeHTML5.co, ReactJS Templates, Astro themes); or when the client is in a well-served vertical. Best practice from the data: pick the template for *structure* (section order, grid, component inventory) and immediately re-skin it with a DESIGN.md — decoupling structure from skin (the ReactJS Templates tri-format approach: same design in Next/React/HTML).
- **Build from scratch** when: the brand is the product (creative agencies, editorial, luxury — where designprompts.dev's most distinctive looks live); the page needs novel interaction (AI prompt-box heroes, islands with custom widgets); or when you want the design system itself to be the reusable asset (then scaffold via Claude Design/DESIGN.md so every future page inherits tokens).
- **The hybrid default for an AI frontend developer:** template or theme for the skeleton → generate/adapt a DESIGN.md for the skin → run the skill-style checklist (contrast, focus, responsive, anti-patterns) before delivery. Templates get you 80% of layout correctness instantly; design-system files get you the last 20% of brand fit and consistency that templates can't.
